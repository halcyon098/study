下面给你 6 条「拿到**普通域用户**且开放 **WinRM/SMB/LDAP/Kerberos**」时常见且可落地的**高层思维流程**（不含具体利用命令/载荷，便于在合法授权的靶场或内网演练中按图索骥）。每条都含：目标、关键检查点、行动要点、成功判据与常见分支。

> 前置共识：以下内容仅用于**合法授权**环境（靶场/自家实验网/甲方授权测试）。思路是高层策略与判据，不提供逐步攻击指令。

------

# 0. 通用前置枚举（所有流程先做一次）

**目标**：把域资产/策略/路径摸清，给后续决策供料。
 **关键检查点**

- 目录与策略：域/林信息、密码策略、锁定策略、域功能级别、信任关系。
- 账户与组：你的当前组、影子/委派相关标志、是否禁用预认证、是否有 SPN。
- 证书服务：是否部署 AD CS、CA/模板清单、是否允许域用户注册证书。
- 资产与共享：关键文件共享、脚本仓、备份目录、部署/运维留痕。
- 图谱：收集 ACL/组关系/委派关系，生成可视化图谱（找最短提权链）。
   **成功判据**：获得一份结构化“地图”（清楚潜在提权边：WriteDACL/GenericAll/委派/证书模板）。

------

# 1. Kerberos 线（AS-REP / Kerberoasting → 破解 → 服务账户入手）

**目标**：利用可离线破解的票据拿下高权服务账户，进而横向到 DC。
 **检查点**

- 是否存在**关闭预认证**的账户（AS-REP roast 入口）。
- 有无**可请求的 SPN** 服务账户（Kerberoast 入口，注意高权/易猜口令）。
- 密码策略强度与可喷射窗口（锁定阈值/时窗）。
   **行动要点（高层）**

1. 抓取可离线破解素材（AS-REP/服务票据），离线破解。
2. 成功拿到服务账户后，评估其**本地管理员范围**与**委派标志**。
3. 若服务账户在服务器上有本地管辖权：通过 WinRM/SMB 登入该服务器，扩展凭据面。
4. 一旦获得任意能对 DC 进行**DCSync** 的身份或落地到 DC 本地管理员，即完成域控控制。
    **成功判据**：离线破解得到高权账户密码或可用哈希 → 服务器本地管理员 → DCSync/域管组。

**常见分支**：

- 破解失败：回到#4（SMB/WinRM 线）做凭据搜集，再回流重试。
- 服务账户非高权：结合#2（ACL 线）走权限放大。

------

# 2. LDAP / ACL 线（图谱找边 → 权限继承/委派滥用）

**目标**：不靠漏洞，直接“用权限打权限”，走 ACL/所有权/委派链。
 **检查点**

- 你的主体对哪些对象有 **WriteOwner/WriteDACL/GenericAll/GenericWrite** 等边？
- 是否对**组对象**或**计算机对象**有可写（含自建计算机配额）？
- 对某些高价值对象（域根、管理员组、服务账户、关键服务器）是否存在可转化的边？
   **行动要点（高层）**

1. 以图谱为导向，选择**最短可达的高价值对象**（如服务器本地管理员组、关键服务账户）。
2. 若能写组：把可控主体**加入**高权组（或添加 SIDHistory/授权 DCSync 权限）。
3. 若能写计算机对象：转#6（RBCD 线）实施资源约束委派。
4. 若能写用户：加 SPN / 调整委派标志 / 改密码策略（依风控而定）。
    **成功判据**：成功把自身或可控主体“抬”到能对 DC 执行 DCSync 或域管组路径。

**常见分支**：

- 没有直连高权边：尝试多跳（组→中间服务器→再提权）、或与#4/#5 联动。

------

# 3. AD CS 线（证书模板误配 → 证书换 TGT → 域控权限）

**目标**：利用 AD 证书服务的模板/发布配置失误，获取可冒充高权身份的证书。
 **检查点**

- 是否部署了 AD CS？能否**域用户自助申请**？
- 模板是否允许**ENROLLEE_SUPPLIES_SUBJECT**、可请求 **Client Authentication**，或存在已知 ESC 场景（如 ESC1/4/8/9 等）？
   **行动要点（高层）**

1. 枚举 CA 与模板，定位**可被普通域用户申请且可做 UPN/SAN 冒充**的模板。
2. 申请证书 → 使用证书走 **PKINIT** 换取目标用户/服务的 TGT/服务票据。
3. 若可冒充高权主体（域管/可 DCSync 主体），直接执行目录复制或加入高权组。
    **成功判据**：拿到可用于高权主体身份验证的证书并成功换取高权限票据（DCSync/域管）。

**常见分支**：

- 模板收紧：回到#2（ACL 线）尝试对模板/CA 对象做权限放大；或转#6（RBCD）。

------

# 4. SMB / WinRM 线（资料搜集 → 凭据扩张 → 横向 → DC）

**目标**：用共享与管理通道“找钥匙圈”，扩张凭据与落地范围。
 **检查点**

- SMB 共享中是否有**脚本/备份/配置**（web.config、部署脚本、自动化凭据、KeePass/备份文件、GPP 残留等）？
- 目标服务器上你是否已是**本地管理员**（决定 WinRM 能否交互）？
   **行动要点（高层）**

1. 有序浏览共享与运维目录，定位**明文/可解密**的凭据与密钥材料。
2. 用新增凭据尝试更多服务器的本地管理员 → 形成“跳板集合”。
3. 在任意服务器上获得足够权限后，转向**目录权限操作**（#2）或**证书/委派**（#3/#6）。
    **成功判据**：获取到额外高价值凭据 → 任意服务器本地管理员 → 进一步达成 DCSync/域管。

**常见分支**：

- 无明文凭据：结合#1 做 roast/喷洒，或#5 查 GPO/GPP 历史遗留。

------

# 5. GPO / 配置线（组策略/历史遗留 → 权限抬升）

**目标**：利用组策略配置/历史残留达成权限提升或落地。
 **检查点**

- 你或你可控主体是否对**某些 GPO 有编辑/链接**权限？
- 是否存在**旧版 GPP cPassword**、启动/登录脚本、计划任务等可被“接管”的位置？
   **行动要点（高层）**

1. 若可编辑/新建并链接 GPO 于某 OU：下发**合规的**管理员配置（如增加本地管理员成员或部署受控证书），在演练环境中验证。
2. 审计历史策略/脚本仓找**硬编码凭据**或错误权限继承。
3. 通过新获得的本地管理员/服务控制权，联动#2/#6 完成域级提升。
    **成功判据**：成功把目标服务器纳入你的受控配置 → 本地管理员 → 域级权限。

**常见分支**：

- 没有 GPO 编辑权：回#2（ACL 线）看能否先拿到对 GPO/OU 的写权。

------

# 6. RBCD / 委派线（计算机对象控制 → 资源约束委派 → 直达关键服务）

**目标**：借助你能控制的**计算机对象**（自建或可写）设置 RBCD，向关键服务冒充高权用户。
 **检查点**

- 你能否**新建计算机对象**（默认域策略常给域用户一定配额）？
- 你能否对某台目标服务器对象写入 **msDS-AllowedToActOnBehalfOfOtherIdentity**？
   **行动要点（高层）**

1. 如果能创建/控制一台“受控机器”对象：把目标服务器配置为允许该机器“代表他人”。
2. 以受控机器身份对目标服务执行**S4U2Proxy**链条，获得代表高权用户的服务票据。
3. 票据落地目标服务器获取本地高权；随后转 #2 完成 DCSync/域管路径。
    **成功判据**：成功代表高权用户访问关键服务 → 目标服务器本地管理员 → DCSync。

**常见分支**：

- 无对象写权：回#2 找 ACL 边；或#3 通过证书拿更高权身份再来设 RBCD。

------

## 协议与阶段对应（快速导航）

- **Kerberos**：#1/#6/#3 的核心（roast、委派、PKINIT）。
- **LDAP**：#0 图谱与 #2 ACL、#3 AD CS、#6 RBCD 都依赖它的信息面。
- **SMB**：#4 搜索凭据与横向落地的主力；也是确认本地管理员的入口。
- **WinRM**：当且仅当在目标上是本地管理员时，成为稳定的管理通道（#1/#4 后半段）。

------

## “完成域控”的常见成功判据（满足其一即可）

- 能以你的主体成功执行 **DCSync**（复制域凭据）。
- 成为 **Domain Admins** / **Administrators@DC** 成员并可稳定登录 DC。
- 能对 DC 或域根对象进行**可持续的 ACL 控制**（WriteDACL/Owner 等）。
- 通过 **AD CS** 获取可代表域管的证书并成功换票进行域级操作。
