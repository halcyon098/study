# Cline 全局工作指南

## 1. 核心原则

- **语言限制**：所有输出和交互必须使用 **中文**。
- **排版要求**：对于任务计划 (Plan)、执行进度 (Task)、总结以及复杂内容，必须使用 **Markdown 表格 (Table)** 格式输出。

## 2. 工具链协同逻辑

在 Linux 远程环境下，请严格遵循以下工具优先级：

| **阶段** | **任务目标**      | **工具**              | **说明**                                                    |
| -------- | ----------------- | --------------------- | ----------------------------------------------------------- |
| **记忆** | 跨会话上下文检索  | **mem0**              | 任务开始前检索相关记忆，结束后存储核心决策与技术点。        |
| **检索** | 全局代码/文件搜索 | **serena**            | 优先进行代码语义搜索，禁止在未定位前盲目读取大文件。        |
| **编辑** | 代码写入与修改    | **apply_patch**       | **唯一首选**：用于精确的代码补丁修改和文件创建。            |
| **视觉** | 复杂操作/环境校验 | **desktop-commander** | 仅在需要视觉确认或 `apply_patch` 无法处理非文本文件时使用。 |

## 3. 强制约束 (Rules)

- **禁止原生 Shell 文件操作**：**严禁**直接调用 `terminal` 中的 `rm`, `cp`, `mv`, `mkdir`, `touch` 或 `redirect (>)` 等 Linux 命令进行文件操作。必须通过上述 MCP 工具（如 `apply_patch`）完成。
- **禁止直接运行 Python 脚本改文件**：禁止编写并运行临时 Python 脚本来修改服务器上的代码或配置。
- **远程路径感知**：由于是远程连接，请务必在操作前确认工作目录路径，确保所有操作都在当前 Project 范围内。
- **错误处理**：若 `apply_patch` 在远程环境下报错，请尝试使用 `serena` 重新扫描文件结构，最后才考虑使用 `desktop-commander` 进行视觉定位。

## 4. 任务执行标准流

1. **Context 检索**：调用 `mem0` 获取历史项目中关于此类环境配置或代码风格的记忆。
2. **任务规划**：以表格形式展示 `当前状态 | 预期目标 | 详细执行步骤`。
3. **定位分析**：利用 `serena` 在文件系统中快速定位目标代码段。
4. **增量修改**：使用 `apply_patch` 提交修改，并确保不会破坏文件权限。
5. **记忆持久化**：完成后将本次解决问题的关键步骤存入 `mem0`
